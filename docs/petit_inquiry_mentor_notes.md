# 助言講師・担当教員用メモ：プチ探究「月データで基地の場所を提案する」

要件定義書 Ver.1.5 §5（層2b）。プチ探究テーマ1「人間の地球外居住で発生する問題を
調査し、その解決策を提案せよ」を選んだグループの伴走用。

## この探究の性格

- **足場は弱い**。データ（5種）と道具（`moonkit`／自由探索ツール）は渡すが、
  問い・「良い場所」の定義・提案は生徒が決める。探究講座（層2a、手順どおり進める解析体験）
  とは目的が違う。
- 根拠：石田（2022）。「自らテーマを決めデータを取得する」経験が「楽しさ」「理解」を
  有意に高める。**ここでの伴走の基本は「答えを教えない・方向を決めない」**。横須賀高校の
  事例でいう「黙って見守る」に近い。
- ただし完全放置ではない。下記の「詰まりやすい点」で、**問い返し**によって前に進める。

## A. RQ 具体化の型（6例）― 伴走の手札

RQ は必ず **「〈目的〉の基地にとって良い場所を、〈データ〉の〈条件〉で探す」** の形にする。
以下は「目的 → 良い場所の定義 → 使うデータ → 分析 → 生徒がハマりやすい点 → 助言の一言」。
**これを生徒に配らない**（教員の手札）。生徒が近い問いに来たら、ハマりやすい点だけ先回りする。

**6例のうち、行き先の半球がばらけるように選ぶ**（氷＝南極／電波天文＝裏側／通信＝表側／
遮蔽＝溶岩チューブ）。全部が南極に向くようなら、それが「南極ありき」に戻っているサイン。

### 例1　☀ 太陽光発電基地（南極の尾根 か 赤道＋蓄電 か）
- 良い場所の定義：太陽が高く（`noon_sun_elev_deg` 大）、夜が冷えすぎず（`night_min_K` 高）、日較差が小さい
- データ：`load('環境')` を `region_type` で「赤道の海」と「南極」に切り、両方 `site_score`。南極を選んだら `極域日照` で細見
- 分析：`site_score(want={'noon_sun_elev_deg':('高い',2),'temp_amp_K':('低い',2)})` を2地域で比べる
- ハマりやすい点：**赤道の「太陽が高い」だけ見て、日較差 300K と 2週間の夜を忘れる**
- 助言の一言：「赤道は太陽が高いけど、夜2週間の電力はどうする？　南極の尾根と比べた？」

### 例2　🔭 電波天文台（裏側・暗くて温度が安定）
- 良い場所の定義：地球の電波が届かない（`earth_elev_deg` が負＝裏側）、1日の温度の振れ幅が小さい
- データ：`region_type(load('環境'), '裏側・赤道（電波天文の候補域）')`（`earth_elev_deg` 低・`temp_amp_K` 低）
- 分析：`site_score(want={'earth_elev_deg':('低い',3),'temp_amp_K':('低い',2)})`。`earth_elevation(lat,lon)` で確かめ
- ハマりやすい点：**地域を選ばず全球で `site_score` すると、日較差が飛び抜けて小さい南極ばかり上位に来る**。まず裏側に絞る
- 助言の一言：「その場所から地球は見える？　見えたら電波望遠鏡としては失格。`earth_elev_deg` は？」

### 例3　❄ 氷採掘基地（南極一択でよい）
- 良い場所の定義：永久影（氷がありそう）に近く、作業機械を置ける程度に平ら
- データ：`dist_to_permanent_shadow(south_pole(load('極域日照')))`（`km_to_shadow` 小・`slope_deg` 低）
- 分析：`site_score(want={'km_to_shadow':('低い',3),'slope_deg':('低い',2)})`
- ハマりやすい点：**永久影の"中"を最適地にして、そこが真っ暗で作業できないことに気づかない**
- 助言の一言：「氷の上に立って掘るの？　電力は？　永久影の"ふち"は考えた？」
- 補足：この目的は答えが南極に近い。それは正しい。「目的が明確だと答えも1つに近づく」ことを言語化させる

### 例4　📡 通信中継基地（表側・地球が高く見える）
- 良い場所の定義：地球が空に高く見える（`earth_elev_deg` が大＝表側）、電力も取れる
- データ：`load('環境')`（`earth_elev_deg` 高・`noon_sun_elev_deg` 高）。`earth_elevation(lat,lon)` で任意地点を確認
- 分析：`site_score(want={'earth_elev_deg':('高い',3),'noon_sun_elev_deg':('高い',1)})`。中心（0,0）付近が最大
- ハマりやすい点：**電波天文台（例2）と `earth_elev_deg` の向きが逆なのを混同する**
- 助言の一言：「通信は地球が"見える"ほど良い、天文台は"見えない"ほど良い。あなたはどっち？」

### 例5　🛡 長期滞在の遮蔽拠点（溶岩チューブ）
- 良い場所の定義：地下空洞（溶岩チューブの天窓）の近く。放射線・微隕石・熱の変動を遮蔽できる
- データ：`load('縦孔')`（既知の天窓7件）＋ `nearest(load('環境'), 縦孔のlat,lon)` でその場所の環境
- 分析：各天窓の周りの `温度`・`区分`・`クレーター` 密度を比べる。裏側（Mare Ingenii）と表側で条件が違う
- ハマりやすい点：**縦孔が地下トンネルに通じている保証はない**（多くは未確認）。位置が7件に固定されている
- 助言の一言：「その縦孔、本当にトンネルに続いてる？　根拠は？　なければ限界に書く」

### 例6　🤖 AI が出した「最適地」の検証
- 良い場所の定義：AI（Gemini 等）が挙げた地点が、本当に条件を満たすか
- データ：全種。AI の主張を1つずつ突き合わせる
- 分析：`nearest(load('温度'/'地質'/'環境'/'極域日照'), <AIの地点>)` でその地点の実測値を出す
- ハマりやすい点：**AI の結論に引きずられ、反証を探さない**。AI は「南極」と答えがち＝それを鵜呑みにする
- 助言の一言：「AI は南極と言った？　目的が電波天文なら、南極から地球は見える？　自分のデータで確かめて」

## B. 追究フェーズのマイルストーン（次に進めてよいか）

伴走者はこのチェックで「まだ次に行かせない」判断をする。**飛ばしたら戻す**。

| # | できていること | まだなら（next の一言） |
|---|---|---|
| M1 | RQ が「〈目的〉の基地にとって良い場所を、〈データ〉の〈条件〉で探す」の形になった | 「"良い場所"を、データのどの数字がどうなっている場所、と言い直せる？」 |
| M2 | 分析の前に**予想を文で書いた** | 「結果を見る前に、どうなると思うか書いて。外れてもいい」 |
| M3 | 1つの指標で**分布を見た**（`hist`／`grid_count`／`scatter`） | 「まず1枚グラフを出そう。全体はどうなってる？」 |
| M4 | **2つ以上の指標**で比べた or 統合した（`site_score`／`summary_by`／2枚の `hist`） | 「その1つの指標だけで決めていい？　ぶつかる条件はない？」 |
| M5 | 予想と結果を**突き合わせ、ズレの理由**を考えた | 下の C の手順へ |
| M6 | 提案地を**1〜数点に絞り**、他の候補と比べて理由を書いた | 「2位じゃなくて1位にした理由は？　どこが違う？」 |
| M7 | データの限界を**3つ以上**書いた | 「このデータで"分からないこと"は？　3つ挙げてみて」 |

夏休み明けに M6 まで来ていれば発表可。M5・M7 が弱いまま発表に向かうグループが多い → そこを重点的に。

## C.「予想と違う結果が出た」ときの指導（4ステップ）

これは探究プロセス（予想 → 反証 → 仮説の修正）そのもの。生徒は**ここを飛ばして次の分析に行きがち**。
伴走者が口頭で 4 ステップを歩かせる（答えは言わない）。

1. **言語化**：「予想は何だった？　結果は何だった？　どこがズレた？」（口に出させる）
2. **前提を疑う**：「その予想は、何を当たり前だと思っていた？」（前提を2〜3個 列挙させる）
3. **仮説を立て直す**：「その前提のどれかが違うとしたら、新しい説明は？」（1つ書かせる）
4. **もう一度データへ**：「その新しい説明、どのデータでもう一回確かめられる？」

例：「海のほうがクレーターが多いと思ったのに少なかった」
→ 前提「隕石は海に多く落ちた」を疑う → 「落ちた数は同じで、後から消えたのでは？」
→ `load('地質')` で海の年代を見る → 海は若い＝溶岩で若返った、と修正。

## 段階ごとの伴走

### 導入（RQを立てる／生成AIを使う）

- **見るべきこと**：問いが「調べ学習」になっていないか。「月面基地はどこがいいか」で
  止まっていないか（大きすぎる）。基地の目的が具体化しているか。
- **生成AIの使い方**：Gemini 等で RQ の案を出させるのは可。ただし**AIの答えをそのまま
  RQにしない**。「AIはこう言ったが、自分たちのデータで確かめられる形になっているか？」を
  必ず問う。AIが挙げた「最適地」を検証するのも立派な探究（むしろ良い）。
- **問い返しの例**：
  - 「その問いは、5つのデータのどれで、どうやって確かめる？」
  - 「『良い場所』ってどういうこと？　データのどの数字がどうなっていれば良い？」
  - 「AIはそう言うけど、根拠は？　自分たちで確かめられる？」

### 追究（データで確かめる）

- **見るべきこと**：
  - **予想を書いてから**分析しているか（葛藤をつくるため）。
  - 予想と違う結果が出たとき、「なぜ」を考えているか。ここを飛ばして次に行きがち。
  - **1つの指標だけで結論を出していないか**（例：日照率だけで決める）。複数の見方をしているか。
    傾斜（`slope_deg`）を忘れていないか（明るい尾根は急なことが多い）。
  - データの限界を無視していないか（極域の温度カーブ、日照率・傾斜の絶対値、クレーターの"今の深さ"、
    円近似の海の割合）。
  - クレーターからの推定を `load('地質')` の USGS 地質図で**答え合わせ**したか。
- **ありがちな行き詰まりと問い返し**：
  | 生徒の状態 | 問い返し |
  |---|---|
  | 分析が「地図を眺める」で止まる | 「数字にすると？　平均は？　海と陸で比べると？」 |
  | 予想が当たって満足して終わる | 「なぜそうなる？　仕組みは？　例外はない？」 |
  | 予想が外れて止まる | 「外れたのはおもしろい。何が予想と違った？　なぜだと思う？」 |
  | `site_score` の重みを適当に決めて終わり | 「重みを変えると答えは動く？　どんな重みでも選ばれる場所はある？」 |
  | 1地点に決めきれない | 「決めきれないのはなぜ？　どの条件がぶつかっている？」 |
  | コード/ツールで詰まる | まず「ヘルパー チートシート」を見せる。それでも詰まれば最小限だけ助ける |
- **技術面**：`moonkit` の使い方はチートシート参照。エラーは日本語で出るものが多い。
  Colab のランタイム切れ（放置で切れる）に注意。

### 夏休み〜発信準備

- 追究の穴（「本当はここも見たかった」）を、無理に埋めず**限界として記録**させる。
  それも成果。
- 発表は「きれいにまとめる」より「何を根拠にどう考えたか」が伝わることを優先。

### 発信（9/27・助言講師の講評）

**評価の観点**：詳細は [`petit_inquiry_rubric.md`](petit_inquiry_rubric.md)（4観点×4段階、附属 SSH ルーブリック
項目2「データや根拠の提示」に整合）。到達水準の具体例は [`petit_inquiry_exemplars.md`](petit_inquiry_exemplars.md)。
講評は点数化より、この4観点でコメントを返す：

| 観点 | 見るところ |
|---|---|
| R1 問いの質 | 「調べ学習」でなく、データで検証できる形に絞れているか。途中で問いを更新したか |
| R2 データや根拠の提示 | 適切なデータを選べたか。1つの指標に頼らず複数の見方をしたか。グラフ・表・数値で示せたか |
| R3 予想との対話 | 予想を立て、外れたときに「なぜ」を考え、仮説を修正したか（C の4ステップ） |
| R4 限界の自覚 | データの限界・考慮できていない要素を自分で言えるか（**この教材の主眼**。弱いなら減点でなく伸びしろとして指摘） |

**講評で避けること**：正解（「本当はここが最適」）を教えること。この探究に唯一の正解は無い
（目的が変われば最適地が変わる、が学びの核）。

## 想定される生徒の提案と、コメントの方向

- **「南極の明るい尾根（日照率50%付近）」**：太陽光基地としては妥当。
  → 「傾斜は？　着陸できる斜面？　温度差はどうだった？　人が住むなら？」
- **「永久影の中（氷採掘）」**：妥当だが要注意。
  → 「そこで作業する電力は？　永久影の"ふち"（平らで少し日も当たる）は考えた？」
- **「南極の平らな地点（傾斜1〜2°）」**：`slope_deg` を使えた点は良い。
  → 「そこ、日は当たる？（一番平らな地点は永久影の中）。目的は何だった？」
- **「赤道近く（着陸しやすい・地球から行きやすい）」**：温度差290Kの問題に気づいているか。
  → 「1日の温度差は？　装置はもつ？　`load('地質')` で海の年代を見た？」
- **「裏側（電波天文台）」**：`earth_elev_deg` を根拠にできていれば良い。
  → 「地球が見えないことを数字で示せた？　通信は中継衛星頼み、を限界に書いた？」
- **「溶岩チューブの天窓の近く（遮蔽拠点）」**：`load('縦孔')` を使えた点は良い。
  → 「その縦孔がトンネルに続く根拠は？（多くは未確認）。位置が7件に固定される制約は？」
- **「複数候補を目的別に提案」**：探究として上出来。
  → 「目的によって答えが**半球ごと**変わることを、どう見せる？　Artemis（極）・LCRT（裏側）・Apollo（赤道）と比べた？」
- **AIが出した最適地をそのまま**：
  → 「`nearest` でその地点の実測値を出した？　AIの根拠は妥当だった？」
- **クレーターの数だけで「海は新しい」と断定**：
  → 「`load('地質')` の USGS 地質図と合っていた？　海の割合は円近似と地質図で同じ？」
